## 🎯 Checklist Déploiement

### 1. CORRIGER LES VERSIONS DES DÉPENDANCES
- [ ] Installer `npm-check-updates` : `npm install -g npm-check-updates`
- [ ] Vérifier les versions : `ncu`
- [ ] Mettre à jour : `ncu -u`
- [ ] Installer : `npm install`
- [ ] Tester build local : `npm run build`

### 2. CONFIGURER LES VARIABLES D'ENVIRONNEMENT VERCEL
Dans Vercel Project Settings → Environment Variables, ajouter :

```
RESEND_API_KEY=<your_resend_api_key>
CONTACT_TO=<your_email_for_contact_form>
CONTACT_FROM=noreply@yourdomain.com
NEXT_PUBLIC_SITE_URL=https://yourdomain.vercel.app

# Base de données admin (voir §2bis)
DATABASE_URL=<postgres_connection_string>

# Auth admin (/admin)
NEXTAUTH_SECRET=<générer avec: openssl rand -base64 32>
NEXTAUTH_URL=https://yourdomain.vercel.app

# Optionnel : upload d'images depuis /admin
BLOB_READ_WRITE_TOKEN=<vercel_blob_token>
```

### 2bis. BASCULER LA BASE DE DONNÉES SUR POSTGRES (obligatoire avant déploiement)
En local, le site utilise SQLite (`prisma/dev.db`) — pratique pour développer, mais **ce fichier ne persiste pas sur Vercel** (serverless, filesystem éphémère). Avant le premier déploiement :

1. Créer une base Postgres gratuite sur [neon.tech](https://neon.tech) (ou l'intégration Vercel Postgres, qui utilise Neon).
2. Dans `prisma/schema.prisma`, changer `provider = "sqlite"` en `provider = "postgresql"`.
3. Renseigner `DATABASE_URL` (en local dans `.env`, et dans Vercel) avec la connection string Postgres fournie par Neon.
4. Lancer `npx prisma migrate deploy` puis `npm run db:seed` pour recréer le schéma et les données de départ sur la nouvelle base.
